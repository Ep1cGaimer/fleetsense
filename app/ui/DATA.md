# Offline evidence export schemas

All files are served from `/data/`, generated by `scripts/export_ui_data.py`, and contain `schema_version`, `run_id` and `data_labels`. No endpoint performs evaluation or exposes a filesystem browser. Fetch failures render an error card.

| File | Payload |
|---|---|
| summary.json | Complete final summary contract in `docs/SUMMARY_SCHEMA.md`; selected verdict, guardrails, policy metrics, counts, manifest, presentation metadata. |
| policies.json | rates, ratios, turnarounds, cells with delta_availability_pp and ci95_pp, frontier threshold rows, metrics keyed by policy, losing_cells. |
| calibration.json | used_horizons; all_cycles, decision_points, near_threshold (each horizon/count/brier/ece/reliability); subgroups (adds subgroup); missed_warnings counts; cycle_zero_decisions. A reliability bin has count, prediction, observed. |
| replay.json | scenario metadata, days array, state-change events, checker_violations, play_days_per_second. Each day has day, stock, in_shop, aircraft array. Each aircraft has aircraft, serial, trajectory, cycle, status, risk. Each event has day, aircraft, serial, event, detail. |
| audits.json | leakage/disjointness/contrast Brier rows, poisoned_future, mutations, sensitivity, horizon, scale, manifest, tests, checker_violations. |
| claims.json | claims array with claim, status, evidence. Generated from fixed registered rows. |
| engine.json | engines array with serial, trajectory, cycle, sensor, cycles, values, horizons, probabilities, band {age,low,high}. The same-cycle P05–P95 band uses final training engines only, not a healthy-fleet reference. Each record is a separately exported terminal snapshot; the UI derives its last-appearance day from replay, not a completion timestamp. Multi-horizon probabilities are terminal-only; selected-day risk is the replay's next-20-cycle scalar. Evaluation-only, not diagnosis. |

Probability zero at cycle zero is the declared no-history prior. Missing statistics and undefined waste ratios are JSON null; they are not replaced with zero.

Routes set `body.dataset.ready` only after their data and Plotly promises resolve. Every root has `data-testid=page-<slug>`; chart hooks remain available for smoke tests. Executable hash routes are `#/fleet`, `#/engine`, `#/engine/<serial>`, `#/policies`, `#/calibration` and `#/audits`. Unknown engine IDs display no substitute. No external fetch, font or CDN is used.

Replay opens at the existing default index 142 (or the last available index for shorter exports), paused. The in-memory selected day, search, filter and sort survive engine navigation and return. The initial table shows pending requests; a day without requests is an honest empty view with an All aircraft action. Local sorting is not scheduling or policy ranking; tied risks use airframe ID and unavailable risks remain last. Request-time urgency is displayed separately from selected-day risk. Serviceability history is computed only from exported daily operational states through the selected day, against a labelled full replay axis. Resource stock does not infer overhaul ordering or return dates.

Policy comparisons and frontiers are precomputed reporting evidence, never execution controls. Registered verdict, intervals, frozen development fallback and budget infeasibility remain separate from relative guardrail results. Calibration tables expose scope-specific engine-cycle sample counts and numeric reliability bins. Validation checks use recorded pass/fail/unavailable outcomes; missing checks are not zero or success. Claim ledger and manifest distinguish measured, proposed and unestablished capabilities.

Negative or null aircraft identifiers in events mean Stores / spare pool, never an invented airframe. Exported day -1 is Initial state — before Day 1. A shop-return event's `detail.new_serial` is shown as its replacement lifecycle ID; this does not establish physical-component continuity. The engine finder searches only local exported serial/source-trajectory records and preserves replay-return context.

Engine, policy, calibration and validation workspaces have sticky entity/scope/return strips and keyboard section links. Section and chart-to-numeric jumps open relevant disclosures and focus their target without changing hash slugs. Sensor readings and training-reference values remain separate numeric exports. Scenario row keys define unplanned/planned downtime ratio and overhaul turnaround days; focus/hover expands the key, and the numeric matrix retains exported intervals.

Policy parameter labels follow the registered policy implementation: HT is an engine-age removal interval in cycles; CT is a health-index threshold with units unspecified; FC is a calibrated failure-risk probability threshold. No condition-metric physical units are invented. Known fewest-failures selection modes are translated for readability; raw codes remain inspectable and unknown modes remain unchanged.
